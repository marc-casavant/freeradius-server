# FreeRADIUS Profiling Scripts

Tools for parsing callgrind profiling results and viewing them in a browser dashboard.

---

## Quick start

Run these commands from the **repo root** after new results have landed in `prof-results/`:

```bash
# 1. Parse raw results → generate JSON files
python3 scripts/profiling/parse_results.py --results-dir prof-results

# 2. (Optional) Remove old raw files outside the retention window
python3 scripts/profiling/prune_results.py --results-dir prof-results --dry-run
python3 scripts/profiling/prune_results.py --results-dir prof-results --apply

# 3. Copy the dashboard into the results directory and serve it
cp scripts/profiling/dashboard/index.html prof-results/index.html
python3 -m http.server 8080 --directory prof-results
```

Then open <http://localhost:8080> in a browser.

## Directory structure

```text
prof-results/
  <branch>/<sha>/<run>/<test-suite>/<test-name>/
    callgrind_report.txt      ← raw profiling input
    valgrind_profiling.log    ← raw profiling input (PID, timestamp)
    valgrind.log              ← raw profiling input (instruction counts, miss rates)
    summary.json              ← generated by parse_results.py
    full.json                 ← generated by parse_results.py
  baselines/<test-suite>/<branch>.json   ← generated by parse_results.py
  index.json                        ← generated by parse_results.py
  index.html                        ← dashboard (copied from scripts/profiling/dashboard/)
```

Raw results are written by the CI profiling workflow. All other files are generated by the scripts below.

## Scripts

### `parse_results.py` — parse raw results into JSON

Reads `callgrind_report.txt`, `valgrind_profiling.log`, and `valgrind.log` from each run leaf under `<results-dir>` and writes:

| Output | Description |
| --- | --- |
| `index.json` | Global index — one lightweight record per run |
| `<branch>/<sha>/<run>/<test-suite>/<test-name>/summary.json` | Per-run summary: totals, top 25 functions, regression flags |
| `<branch>/<sha>/<run>/<test-suite>/<test-name>/full.json` | Per-run detail: all functions + rolling baseline stats |
| `baselines/<test-suite>/<branch>.json` | Window aggregate: best/worst/median per function |

**Run from the repo root:**

```bash
python3 scripts/profiling/parse_results.py --results-dir prof-results
```

**Useful flags:**

| Flag | Default | Description |
| --- | --- | --- |
| `--results-dir` | `prof-results` | Path to the results directory |
| `--output-dir` | same as `--results-dir` | Where to write generated JSON (rarely needed) |
| `--window-days` | `7` | How many days back the rolling baseline looks |
| `--window-runs` | `200` | How many runs back the rolling baseline looks |
| `--quiet` | off | Suppress per-run progress output |

Run this script every time new profiling results arrive — either manually in CI after the profiling-tests job, or locally after pulling new results.

---

### `prune_results.py` — delete old raw files

Removes `callgrind_report.txt`, `valgrind_profiling.log`, and `valgrind.log` from runs that fall outside the retention tiers. Generated files (`summary.json`, `full.json`) are **never deleted**.

> **Run `parse_results.py` first.** The pruner reads `summary.json` to identify runs; leaves without it are skipped.

**Retention tiers:**

| Age | What is kept |
| --- | --- |
| 0 – 30 days | All raw files |
| 30 – 60 days | Half (every other run per day) |
| 60 – 90 days | Last run of each day |
| 90 days – 1 year | Last run of each Sunday and Wednesday |
| 1 year + | Last run of each month |

Runs listed in `prof-results/pins.json` are always kept.

**Always dry-run first:**

```bash
python3 scripts/profiling/prune_results.py --results-dir prof-results --dry-run
```

**Then apply:**

```bash
python3 scripts/profiling/prune_results.py --results-dir prof-results --apply
```

## Viewing the dashboard

The dashboard fetches JSON over HTTP and **cannot be opened directly as a file** (`file://` URLs will fail due to browser CORS restrictions).

**Serve the dashboard locally:**

```bash
# From the repo root
cp scripts/profiling/dashboard/index.html prof-results/index.html
python3 -m http.server 8080 --directory prof-results
```

Open <http://localhost:8080> in a browser.

The dashboard reads from the same `prof-results/` directory. Re-run `parse_results.py` any time new results arrive and refresh the browser — no server restart needed.

## Full workflow (in order)

```bash
# 1. Pull or sync new profiling results into prof-results/ (done by CI)

# 2. Parse
python3 scripts/profiling/parse_results.py --results-dir prof-results

# 3. (Optional) Preview and apply pruning
python3 scripts/profiling/prune_results.py --results-dir prof-results --dry-run
python3 scripts/profiling/prune_results.py --results-dir prof-results --apply

# 4. View
cp scripts/profiling/dashboard/index.html prof-results/index.html
python3 -m http.server 8080 --directory prof-results
# → open http://localhost:8080
```
